# i18n

`@ngx-translate/core`, six bundles in `src/assets/i18n/`: `es` (source language), `en`, `de`,
`fr`, `it`, `pt`. The bundles share the same keys and line count — a `wc -l` mismatch means a
language was missed.

## Namespaces

| Namespace | Surface |
|---|---|
| `dashboard.*` | Inicio |
| `pantry.*` | Despensa page and all its modals and sheets (incl. `pantry.receiptScan.*`) |
| `shopping.*` | Shopping list (route `/list`; the key name predates the route) |
| `insights.*` | Análisis |
| `settings.*` | Settings and sub-pages |
| `onboarding.*`, `upgrade.*`, `pro.*` | Onboarding, paywall, PRO copy |
| `notifications.*` | Local notification titles and bodies |
| `emptyStates.*`, `common.*` | Shared empty states, buttons (`common.actions.*`), dialogs |

## Adding keys

1. Add the key to all six bundles in the same change. Script it when touching several keys:
   the files round-trip byte-identically through `JSON.stringify(obj, null, 2) + '\n'`, so a
   parse → set → write script produces a clean additions-only diff.
2. Translate each language properly; don't copy Spanish into the others.
3. Never rename or reuse an existing key for a different meaning: `EmptyStateComponent` reports
   its `subtitleKey` to analytics, so keys double as identifiers.
4. Pass keys (not translated strings) to `ToastService` and `EmptyStateComponent` (`subtitleKey`).

## Interpolation

- `{{ 'ns.key' | translate: { name } }}` in templates, `translate.instant('ns.key', { name })` in TS.
- Never concatenate translated fragments; put the variable in the string.
- Plurals: `<key>_one` plus `<key>`, chosen in code by count.

## Wording

- Match the UI's words, not the code's: the star is "Mantener siempre en casa"
  (`pantry.form.basic`), never "básico".
- Second person, short, sentence case. Menu actions are short verb phrases ("Ocultar por ahora", "Quitar de la lista").
